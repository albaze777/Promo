# OredLab — "One Line"

A 26-second cinematic identity film for **OredLab** (an art community for creators) and **Ored** (the AI being built from scratch alongside it): 22.5 s of story and a held end card. Every frame is generated by code. No footage, stock imagery, downloaded artwork or AI-generated media is used.

> One line of existence becomes the universe, then life, then humanity, then art, then digital creation, then intelligence, then Ored, then OredLab.

**Rendered film:** `renders/oredlab-promo.mp4`, 1920×1080, 60 fps, 8 motion-blur sub-frames, H.264 (CRF 21) + AAC, 26 s, 43 MB. `renders/oredlab-promo_share.mp4` is the same film at 8.4 Mbps (26 MB) for messaging and social uploads. The CRF 16 master (about 300 MB) is reproduced by `bun run render` into `out/`. Regenerate it with the commands below.

- Concept, palette, typography, beat map and scene-by-scene treatment: [`docs/TREATMENT.md`](docs/TREATMENT.md)
- Engine, scene API, determinism rules and the motion-blur renderer: [`docs/ENGINE.md`](docs/ENGINE.md)

## Requirements

- [bun](https://bun.sh) ≥ 1.1
- ffmpeg with libx264 and aac
- A Chromium or Chrome for the offline renderer, driven headless through playwright-core. The script looks for `$CHROME_PATH`, then the Playwright cache in `$PLAYWRIGHT_BROWSERS_PATH` (default `/opt/pw-browsers`), then an installed Chrome.

```sh
bun install
```

## Preview (real time, in the browser)

```sh
bun run dev              # → http://localhost:5173   (?t=11 starts at 11 s, &scale=2 previews 4K)
```

| key | action |
|---|---|
| space / click | play / pause (with the procedural soundtrack) |
| ← / → | step one beat (0.625 s), with ⇧ ±1 s |
| , / . | step one frame |
| [ / ] | previous / next scene |
| c | jump to the next cue |
| l | loop the current scene |
| s | save a PNG still of the current frame |
| m | mute |
| h | hide the timeline UI |

The timeline bar shows the scene windows (click one to jump to it) and a tick for every cue. The preview and the offline renderer run **the same code** (`Engine.render(t)`). The only difference is that the export averages motion-blur sub-frames.

## Render

All modes start a private Vite server (with live reload off) and headless Chromium. Output goes to `out/`.

```sh
# the film: 1080p60, 8 motion-blur sub-frames per frame, H.264 CRF 16 + AAC
bun run render                          # = bun scripts/render.ts video --samples 8 --shutter 0.5 --out out/oredlab-promo.mp4
bun scripts/render.ts video --jobs 2 ...  # split into parallel segments, then a lossless concat

# 4K (true 3840×2160: every layer and line is rendered at full resolution, not upscaled)
bun run render:4k                       # = ... --scale 2 --out out/oredlab-promo-4k.mp4

# a quick draft of the whole film (no motion blur, 30 fps)
bun scripts/render.ts video --samples 1 --fps 30 --preset veryfast --out out/preview.mp4

# one scene (its timeline window)
bun scripts/render.ts scene art         # origin | world | human | art | digital | ored | outro

# a time range
bun scripts/render.ts video --from 8.75 --to 13.1 --out out/art.mp4

# still frames (PNG, full resolution), optionally only loading some scenes
bun scripts/render.ts stills --t 0.6,6,11.5,24 --out out/stills
bun scripts/render.ts stills --t 11.5 --only art --samples 8     # with motion blur

# contact sheets
bun scripts/render.ts sheet --from 0 --to 26 --n 48 --cols 6 --out out/sheet.png
bun scripts/render.ts sheet --cuts --out out/cuts.png            # frames around every scene boundary

# frame timing
bun scripts/render.ts perf --from 0 --to 25 --step 1 --samples 8
```

Renderer options: `--fps`, `--samples N` (motion-blur sub-frames), `--shutter` (fraction of the frame interval), `--crf`, `--preset`, `--x264`, `--jobs`, `--scale`, `--noaudio`, `--angle <backend>` (ANGLE backend: `swiftshader` by default on Linux, `metal` on macOS, `default` for a real GPU), `--url` (to reuse a running dev server).

On a machine without a GPU (SwiftShader) a 1080p frame takes about 1–8 s with 8 sub-frames, so the whole film takes one to two hours, or less with `--jobs 2`. With a real GPU (`--angle default`, or the default `metal` on macOS) it is many times faster.

## Timing

All times on the command line (`--t`, `--from`, `--to`, `?t=`) are **output seconds** (0–26). Scenes and cues are authored on a story clock (0–20.8). The film plays it `TIME_SCALE` = 1.25× slower: one constant in `src/timeline/cues.ts` re-times the picture and the sound together. The preview's status line shows both clocks.

## Sound

```sh
bun run audio            # → public/audio/promo.wav  (deterministic procedural sound design)
```

The soundtrack is synthesised from the same cue sheet as the picture (`src/timeline/cues.ts`). The film is cut on a 96 BPM grid (the 120 BPM story grid played at `TIME_SCALE` 1.25), so licensed music can replace it later without re-timing anything. `--noaudio` renders silent.

## Layout

```
src/
  main.ts                preview player + export API (window.__promo)
  brand.ts               every brand value: name, tagline, URL, palette, fonts
  engine/                renderer core: engine (timeline, compositing, motion blur), gl, post, lines, scene API
  timeline/              cues.ts (the beat/cue sheet) · timeline.ts (scene windows)
  scenes/                sceneOrigin · sceneWorld · sceneHuman · sceneArtEvolution · sceneDigitalArt · sceneOred · sceneOutro
  motifs/                line.ts (THE LINE, used by every scene) · orbit.ts / world.ts / ored.ts (hand-off geometry)
  shaders/               common GLSL (noise, SDFs, AA lines) · topo.ts (planet / dive / hand / stone)
  art/                   paint.ts (brush toolkit) · eras.ts (six eras of one artwork) · gallery.ts (13 original pieces) · plates.ts
  typography/            bundled fonts (fontsource, SIL OFL) and Canvas2D type helpers
  utils/                 math, easing, seeded RNG, CPU noise replica of the GPU terrain
scripts/
  render.ts              offline renderer: stills / sheet / scene / video / perf (headless Chromium → ffmpeg)
  audio.ts               procedural sound design
docs/                    TREATMENT.md (style bible) · ENGINE.md (developer guide)
```

## Brand note

oredlab.com could not be reached from the build environment. The identity follows public information about the platform: "Ored – the art community", a curated home for digital artists, and an AI built from scratch. The red signature colour comes from the name: O·**red**. The real logo, palette or fonts can be dropped into `src/brand.ts` without touching scene code. The end-card wordmark is set in Instrument Sans, and its O is the ring drawn by the line.
